# feat-config-setup — Интерактивная настройка конфига при первом запуске, ЗАВЕРШЕНО

<!-- Новый модуль config.py: загружает токены из shabbot.env или интерактивно спрашивает. Вышел в v0.2.0. -->

### 2026-06-12 — DONE: config module с .env поддержкой и интерактивным промптом

**Цель:** Бот падал с `KeyError` при запуске без переменных окружения. Нужна была нормальная установка без `source shabbot.env` — особенно актуально для Docker и свежей pipx-установки.

**Сделано:**
- Новый `shabbot/config.py` — загружает `shabbot.env` через python-dotenv если файл есть, иначе интерактивно спрашивает `SHABBOT_TOKEN` и `TODOIST_TOKEN`, предлагает сохранить
- Добавлена зависимость `python-dotenv>=1.0` в `pyproject.toml`
- `bot.py` и `todoist/client.py` переведены на `load_config()` вместо прямого `os.environ`
- Whisper-константы (`large-v3-turbo`, `"whisper"`) захардкодены в `bot.py` — убраны из конфига и из env

**Решения:**
- `WHISPER_MODEL` и `WHISPER_BIN` не попали в конфиг — модель зафиксирована (`large-v3-turbo`), путь к бинарнику не нужен если whisper в PATH. При Docker добавим как env var отдельно
- Сохранение в `.env` только при первом запуске (файл не существует) — не перезаписываем существующий чтобы не потерять кастомные значения
- Не использовали `python-decouple` или `pydantic-settings` — overkill для двух токенов
- Три отдельных коммита: (1) модуль + зависимость, (2) хардкод whisper, (3) замена os.environ на config

**Не делали:**
- `WHISPER_MODEL` / `WHISPER_BIN` в конфиг — отложено до Docker-задачи
- Валидация токенов (формат, проверка через API) — нет смысла без реального запроса

**Побочные эффекты:**
- `import os` удалён из `bot.py` — подсветил ruff, поймано локальным прогоном перед пушем
- PSR выпустил `v0.2.0` автоматически после мержа
